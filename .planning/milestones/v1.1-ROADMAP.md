# Milestone v1.1: Debug-Ready

**Status:** ✅ SHIPPED 2026-05-17
**Phases:** 10–12
**Total Plans:** 9

## Overview

v1.1 makes Shop2Parcel fully observable. Every poll now scans all emails in the configured window (no skip gates), deduplication shifts from message-IDs to persisted tracking numbers, and a rich per-email activity log exposes exactly what was found, matched, and submitted. HA's native debug toggle activates comprehensive per-layer verbose logging. A v1.1.1 patch addressed code review findings and split the monolithic coordinator into subclasses.

## Phases

### Phase 10: Full-Window Scanning & Tracking Dedup

**Goal**: Every poll reliably processes all emails in the configured window with no missed shipments, while preventing duplicate submissions via tracking-number-based deduplication that survives HA restarts
**Depends on**: Phases 1–9 complete (v1.0 shipped)
**Requirements**: SCAN-01, SCAN-02, SCAN-03, DEDUP-01, DEDUP-02, DEDUP-03
**Plans**: 3 plans

- [x] 10-01: Add const.py helpers + simplify gmail_client.build_incremental_query + convert imap_client to SINCE-date search
- [x] 10-02: Coordinator refactor: Shop2ParcelStore v1→v2 migration, tracking-number dedup, remove forwarded_ids/timestamp/UID fields
- [x] 10-03: Delete button.py + tests/test_button.py, shrink PLATFORMS to [sensor, binary_sensor]

**Key decisions:**
- `normalize_tracking_number` placed in `const.py` (no circular imports)
- `MAX_SUBMITTED_TRACKING_NUMBERS = 1000`; LRU via `OrderedDict.popitem(last=False)`
- IMAP SINCE-date search replaces UID-range approach
- `build_incremental_query` simplified to `(base_query, rescan_window_days)` only
- `button.py` deleted entirely — `async_reset_forwarded_ids` removed in Plan 02
- MINOR version bump to v1.1.0 (stable, not pre-release)

### Phase 11: Activity Log & Debug Logging

**Goal**: Every poll produces a structured, inspectable record of what was scanned and why each email succeeded or was skipped; full operational detail available via HA's native debug logging toggle
**Depends on**: Phase 10
**Requirements**: ACTLOG-01, ACTLOG-02, ACTLOG-03, ACTLOG-04, ACTLOG-05, DBG-01, DBG-02, DBG-03, DBG-04, DBG-05
**Plans**: 3 plans

- [x] 11-01: PollStats ring buffer (deque maxlen=50) + scan event append at all 10 exit points (5 Gmail + 5 IMAP) + unit tests
- [x] 11-02: Debug logging: add _LOGGER to gmail_client.py + parcelapp.py; add _LOGGER.debug calls to coordinator, email_parser, all API clients
- [x] 11-03: ActivityLogSensor (6th diagnostic sensor) + diagnostics.py deque serialization fix + activity_log top-level key + tests

**Key decisions:**
- `collections.deque(maxlen=50)` for ring buffer — auto-eviction built-in
- Scan event dict uses `'sender'` key (not `'from'`) to avoid Python keyword collision
- `scan_events` and `scan_events_total` NOT reset per poll — accumulate across HA session lifetime
- `extra_state_attributes` slices to `list(scan_events)[-10:]` to cap HA state attribute payload
- `diagnostics.py` explicitly converts `scan_events` deque to list after `dataclasses.asdict()`
