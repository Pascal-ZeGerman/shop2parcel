## v1.1 Requirements (All Complete)

### Full-Window Scanning (SCAN)

- [x] **SCAN-01**: Coordinator scans ALL emails in the `rescan_window_days` window on every poll — no message-ID or IMAP UID skip gate
  - *Outcome: Validated — Phase 10 removed `last_seen_message_id` from Gmail and `last_imap_uid` from IMAP paths entirely*
- [x] **SCAN-02**: Gmail coordinator query boundary is solely the `after:` date filter derived from `rescan_window_days` (not `last_seen_message_id`)
  - *Outcome: Validated — `build_incremental_query` simplified to `(base_query, rescan_window_days)` only*
- [x] **SCAN-03**: IMAP coordinator fetches all UIDs in the folder from `(now − rescan_window_days)` on every poll (not filtered by `last_imap_uid`)
  - *Outcome: Validated — IMAP switched to SINCE-date search*

### Submission Dedup (DEDUP)

- [x] **DEDUP-01**: Coordinator maintains a persisted set of already-submitted tracking numbers in HA Store (`submitted_tracking_numbers`), surviving HA restarts
  - *Outcome: Validated — `Shop2ParcelStore` v2 with `OrderedDict[str, None]` + LRU cap 1000*
- [x] **DEDUP-02**: Before POSTing to parcelapp.net, coordinator checks `submitted_tracking_numbers` — matching tracking numbers are skipped without an API call
  - *Outcome: Validated — `normalize_tracking_number` dedup check before every POST*
- [x] **DEDUP-03**: After a successful POST, coordinator adds the tracking number to `submitted_tracking_numbers` and immediately persists the Store
  - *Outcome: Validated — immediate `async_save_store()` after each successful POST*

### Activity Log (ACTLOG)

- [x] **ACTLOG-01**: Coordinator maintains an in-memory ring buffer of the last 50 per-email scan events; buffer resets on HA restart
  - *Outcome: Validated — `collections.deque(maxlen=50)` in `PollStats`*
- [x] **ACTLOG-02**: Each scan event records: timestamp, message identifier, email subject, sender, template strategy used (or "no_match"), tracking number extracted (or null), submission outcome
  - *Outcome: Validated — all 10 exit points (5 Gmail + 5 IMAP) emit structured event dicts. Note: ParcelAppTransientError/InvalidTrackingError paths don't emit events (tech debt)*
- [x] **ACTLOG-03**: Existing counter sensors (emails_scanned, emails_matched, tracking_numbers_found, keyword_hits) are preserved unchanged — activity log is additive
  - *Outcome: Validated — existing counters untouched; scan_events added alongside*
- [x] **ACTLOG-04**: The activity log ring buffer is included in the HA diagnostics download
  - *Outcome: Validated — `activity_log` top-level key in diagnostics.py output*
- [x] **ACTLOG-05**: A new diagnostic sensor entity exposes the last 10 scan events as `extra_state_attributes` (entity state = total events logged since last HA restart)
  - *Outcome: Validated — ActivityLogSensor (6th diagnostic sensor) added*

### Debug Logging (DBG)

- [x] **DBG-01**: All verbose/per-email processing output uses `_LOGGER.debug()` — INFO level is limited to user-actionable events
  - *Outcome: Validated — per-email processing consistently at DEBUG level*
- [x] **DBG-02**: Gmail and IMAP coordinators log at DEBUG per poll: query string / server+folder, message count returned, per-message processing decision
  - *Outcome: Validated — poll-start and per-message DEBUG calls added*
- [x] **DBG-03**: EmailParser logs at DEBUG per message: templates attempted in order, match/reject reason, data extracted
  - *Outcome: Validated — `_LOGGER.debug()` calls in email_parser.py for each carrier detection attempt*
- [x] **DBG-04**: ParcelAppClient logs at DEBUG per API call: tracking number, HTTP response code, or skip reason
  - *Outcome: Validated — DEBUG calls added to parcelapp.py for each POST attempt*
- [x] **DBG-05**: Debug logging is activated via HA's native integration debug toggle — no additional integration-side configuration required
  - *Outcome: Validated — standard Python `logging.getLogger(__name__)` pattern; HA debug toggle controls level*
